# 1.1.10 自动下载网络设置

## 用户入口

设置里有两个独立开关，整行都可触摸，支持读屏 Switch 语义；不再有不可点击的「离线下载」分组标题。

- 加书后自动下载：保留既有启用值和开关行为，关闭时取消尚未完成的自动待办；再次开启只影响之后明确新加的书，不补扫原书架。
- 仅在不计费 Wi-Fi 下自动下载：默认开启。总开关关闭时保持可见、置灰，并保留此前选择。只有总开关开启、用户明确关闭此限制后，自动任务才可使用计费 Wi-Fi、移动数据或其他在线网络。

1.1.9 的 `global-auto-download-v1/enabled` 不改键、不重置。新键 `wifi-only` 缺失即为 true，故覆盖升级不自动扩大网络许可。旧 BookHub-only 到全局的历史迁移仍遵循原规则，不重新启动已取消的旧待办。

## 队列与运行时

BookHub 原队列和古登堡/OPDS/基础规则的独立队列统一采用新偏好。严格模式给 JobScheduler UNMETERED 约束，并额外检查实际 Wi-Fi；放开限制后为 ANY，但仍要求在线、自动下载已开启及来源许可。来源授权、限速、完整性和空间检查不变。

切换限制只替换活跃自动任务的执行 nonce，保留书籍身份、job ID、队列记录、有效部分内容和阅读锚点，再取消旧调度并按新约束重新安排。旧传输在检查点停止，不能发布或重新标记新执行。独立源同一本仍有在途执行时，新任务请求系统退避重试，不并发重复下载。旧执行的停止、完成回调不能更改新 nonce 的任务。已经完整或真正失败的任务不因切换设置被反复重下。

自动下载调用保留一个始终读取最新偏好的 guard，而不是把开工时的网络选择捕获到整个传输。内层下载器在自动路径允许由该 guard 做决定；手动路径仍原样使用单次选择，不能被全局放开限制覆盖。当前账号/来源及旧权限检查始终存在；不扫描其他账号或整座书架。

系统决定实际执行时间，不承诺切换后立即完成。已在途的网络数据无法撤回；测试验证的是后续请求、传输检查点和内容提交被新策略阻止，没有进行真实流量计费测试。

## 验证

主机原生 Android / Compose 通过设置入口使用坐标触摸整行开关，验证默认、置灰、反复切换、重建 ViewModel 后持久化、升级保留启用状态、窄屏大字与深色。主机截图是实际 Compose 渲染，不是手机实拍。

受控 NetworkCapabilities 分别模拟计费 Wi-Fi、蜂窝、不计费非 Wi-Fi 与不计费 Wi-Fi；合成资料验证待办约束替换、运行中重新开启限制、旧响应不能发布、恢复/冷启动与相同 ID 不重复任务。BookHub 用自写阅读包和模拟会话验证；独立源保留真实适配器的本机协议测试。手动严格下载在全局放开后仍被阻止，主动选择流量可完成。

环境没有模拟器或 /dev/kvm；没有实际设备 pm install -r、系统后台调度/杀进程、真实网络切换或流量测试，没有真实 BookHub 账号操作。签名和存储兼容测试不等于实机升级。源文件、阅读坐标、会话和下载目录格式保留。

参考平台契约：[JobScheduler](https://developer.android.com/reference/android/app/job/JobScheduler)、[JobService](https://developer.android.com/reference/android/app/job/JobService)。
